# 街角自習咖啡廳 MVP

## 1. 建立專案與安裝套件
```bash
npm create vite@latest study-cafe -- --template react
cd study-cafe
npm i three @react-three/fiber @react-three/drei @supabase/supabase-js lucide-react
npm i -D tailwindcss @tailwindcss/vite     # Tailwind v4；v3 請照官方文件設定
```
把本資料夾的 `src/` 覆蓋進去（`App.jsx` 取代原本的；`main.jsx` 維持 Vite 預設即可），
Tailwind v4 在 `src/index.css` 第一行放 `@import "tailwindcss";`，並在 `vite.config.js` 加入 `@tailwindcss/vite` 外掛。

## 2. Supabase
1. 建立專案 → Authentication → Providers → Email：開發階段可先關閉 "Confirm email"。
2. SQL Editor 貼上並執行 `supabase/schema.sql`（已跑過舊版 6 座位的人改跑 `upgrade_to_12_seats.sql`）。
3. 若 `pg_cron` 報錯：Database → Extensions 啟用 pg_cron 後重跑最後兩段。
4. `.env.local`：
```
VITE_SUPABASE_URL=https://xxxx.supabase.co
VITE_SUPABASE_ANON_KEY=eyJ...
```
5. `npm run dev`，開兩個瀏覽器（一個無痕）註冊不同帳號即可看到彼此入座。

## 3. 讀書計畫 / 甘特圖 / 排行榜 / 獎勵（新功能）
1. Supabase → SQL Editor 執行 `study_planner.sql`（需先執行過 `cafes_calendar_24_seats.sql`）。
2. 大廳或咖啡廳左上角面板 →「讀書計畫」：新增項目（內容、預計時數、難度、最晚完成日、打算讀的星期與時段），系統自動排好每天的區塊並畫出甘特圖。
3. 每個區塊讀完就勾選 → 獲得 XP、連續天數、徽章、升級；「排行榜」可看今日 / 累計 / 經驗值排名，點任何名字（排行榜、聊天室、3D 場景名牌）可看總讀書時間與今天讀書時間。
4. 排程演算法在 `src/lib/scheduler.js`（分散練習、交錯練習、間隔複習、時間緩衝、晝夜節律、避開行事曆行程）。

## 9. 修正：專注時間結束沒有被記錄 ＋ 提前結束 / 專注紀錄清單
**原因**：以前只靠瀏覽器的 `setTimeout` 在「時間到」那一刻寫入。讀書時切到別的分頁 / 手機鎖屏，瀏覽器會暫停心跳，
伺服器 cron 90 秒後把座位當幽靈座位釋放，計時器跟著消失 → 沒有紀錄；寫入失敗時也只有 console 警告，不會重試。

**修法（改由資料庫保證記錄）**：
- `focus_log_fix.sql`（**請到 Supabase → SQL Editor 執行一次，可重複執行**）
  - `cafe_seats` trigger：專注階段跑完後，座位只要被離開 / 換狀態 / 換人，就補寫一筆 `focus_logs`
  - `pg_cron` 每分鐘掃描：跑完但人還坐著的階段也補記（`log_finished_focus_sweep`）
  - `release_stale_seats`：專注倒數沒跑完時，不因心跳中斷踢人（跑完 + 90 秒才清）；`claim_seat` 可接手沒有心跳的座位
  - RPC `log_my_finished_focus`（前端時間到時確認）、`end_focus_early`（提前結束）
  - 重複防護：同一階段（`started_at` 差 1 秒內）只會有一筆，前端 / trigger / cron 同時寫入也不會重複
- 前端
  - `useFocusLogger.js`：時間到、回到分頁、視窗取得焦點、網路恢復、從 bfcache 還原都會檢查；失敗自動重試（2/5/15/30/60 秒）；
    全部失敗才跳出警告。資料庫還沒更新時自動退回舊的直接寫入，不會壞掉。
  - 時間到 / 提前結束後顯示「✅ 已記錄專注 N 分鐘」，綁定今日計畫的話一併完成區塊並加 XP。
  - 今日計畫的綁定改存 `localStorage`（`src/lib/pendingPlan.js`），重新整理或關網頁再回來也能補完成。
  - `pagehide` 進入 bfcache（手機切換 App）時不再誤釋放座位。

**新功能**
- **提前結束**（專注面板）：依實際專注分鐘數記錄（至少 1 分鐘），座位改成休息；不算完成計畫區塊。
- **時間到提示**：面板顯示「這一輪已自動記錄」。
- **行事曆專注紀錄**：點選某一天，會列出當天每一輪的任務、開始時間、分鐘數，月曆下方顯示本月總專注時間。

**部署順序**：① 先執行 `focus_log_fix.sql` → ② 再部署前端。舊版前端在 SQL 更新後仍可運作。
**注意**：修正前已經漏掉的紀錄無法補回。專注中心跳中斷時座位會保留到倒數結束，因此關掉電腦蓋子也可能被算成跑完一輪
（與「分頁開著不看」本來就無法區分）；若要更嚴格，可把 `release_stale_seats` 的寬限改短。

## 9. 本週排行榜、烘焙階段
- **排行榜新增「本週」**（週一 00:00 起，本地時間）：排行榜與使用者資料卡都會顯示 今天 / 本週 / 累計 讀書時間。
- **每種咖啡豆都要經過 淺焙 → 中焙 → 深焙 → 重焙**：重焙之後才換成下一種更高級的豆子（20 種 × 4 階段 = 80 級）。每升 1 級前進 1 個階段；完成者獎勵會直升 1 級。資料卡有烘焙程度標籤與咖啡豆圖鑑。
- **等級曲線改成較平緩**：`level = floor((xp/50)^(2/3)) + 1`（SQL 的 `study_level()` 與前端 `levelFromXp()` 必須一致）。原本的曲線在 80 級需要約 31 萬 XP，改後約 3.3 萬 XP。**既有使用者的等級會因此重算（通常會變高）。**
- **部署**：重新執行 `study_planner.sql`（會重建 `study_leaderboard`、`study_user_card` 兩個函式），再重新部署前端。

## 大廳人數與咖啡廳裡不一致（修正）
**問題**：大廳以前只數「資料庫有座位＋最近有心跳」的人，咖啡廳裡看到的卻是「Presence 線上＋站著走動的人」。
所以站著走動、沒入座的人，大廳顯示沒人；反過來，專注中關網頁的人座位會保留，大廳又會顯示有人。

**現在**：大廳和咖啡廳裡用同一份資料（Presence），兩個方向都不會再對不上（只改前端，不需要執行 SQL）：
- `N 人在線` = 該咖啡廳 Presence 裡的人（坐著、站著、走動都算），等於進去後左上角的人數。
- `N/24 入座` = 資料庫有人的座位，且那個人還在線（不在線的幽靈座位視為空位，和咖啡廳裡的畫面一致）。
- 咖啡廳沒人 → 一定顯示 0 人，就算資料庫還保留著幽靈座位。
- 只有 Presence 連不上時才退回 `cafe_seat_counts`（心跳計數，需要 `lobby_counts_fix.sql`），不會用原始座位資料。

實作：`src/hooks/useLobbyPresence.js`（用獨立的 Supabase client 旁聽各店 Presence，不會和咖啡廳裡的頻道衝突）、
`src/lib/lobbyStats.js`（計數規則）、`src/components/CafeLobby.jsx`。
